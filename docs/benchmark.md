# 性能与正确性测量报告

> 本报告是 nano-vllm-specdec 全部测量数据的正本：配置口径、三负载吞吐、正确性验证、负载设计方法学，以及已知边界。所有数字可在对应工具脚本上一条命令复现（见文末）。

## 1. 测量配置与口径

| 项 | 值 |
|---|---|
| 硬件 | RTX 3080 Ti（12GB, Ampere sm_86），AutoDL 按量实例 |
| 模型 | Qwen3-0.6B（bf16） |
| 投机参数 | `k=4`（默认值，未做全扫描，见 §7）；`min_ngram=2, max_ngram=8` |
| 执行模式 | `enforce_eager=True` |
| 采样 | greedy（历史数据以 τ=1e-6 采集；`temperature=0` 路径已验证与其输出全等，见 §4.1） |
| 计时 | 引擎外墙钟（`time.perf_counter`），吞吐 = completion token / 墙钟——进度条的 Decode 显示是轮/s 不是 token/s，不可直接用 |

**口径声明（诚实条款）**：

- **每配置单轮测量**。排除一次性开销的纪律是 warmup：首跑曾因 `torch.compile` 首次编译（约 4-5s）计入首个负载的 A 路，导致加速比虚高至 x4.49；加 warmup（建引擎后小 generate 烧掉编译）后修正为 x2.04。计时对照必须防一切一次性开销。
- 单轮不设均值，但有两层交叉验证兜底：① 独立的 monkey-patch 实测（M2，单序列逐轮计数：41 轮 spec、每轮稳定接受 3、45 轮产 127 token 账目全平，吞吐 ~57 vs 逐 token 25-28 tok/s ≈ 2x）；② greedy 确定性使统计量可复现（三组独立运行 spec 轮数 / 接受分布逐字段全同）。
- 对照原则：同实例、同负载、同参数，A 路（关投机）先跑、B 路（开投机）后跑；A→B 之间清空 hash 表，防前缀缓存残留让 B 白捡加速。

## 2. 三负载吞吐（`spec_bench.py bench`）

| 负载 | prompt 形态 | 关投机 | 开投机 | 加速比 | spec 轮占比 | 接受分布（token 数→轮数） |
|---|---|---|---|---|---|---|
| 逐字复述 | "把下面这句话原样重复 10 遍" | 25.2 tok/s | 51.4 tok/s | **x2.04** | 14/18 | {5:12, 4:1, 1:5} |
| 数数（伪模式） | "从 1 依次数到 60" | 27.5 tok/s | 26.7 tok/s | x0.97 | 104/185 | {1:182, 2:2, 5:1} |
| 开放生成 | "写 200 字介绍你自己" | 29.4 tok/s | 29.1 tok/s | x0.99 | 1/59 | {1:59} |

逐桶解读：

- **复述**：18 轮 decode 中 14 轮走投机，其中 12 轮吃满 5 token（4 草稿全收 + 1 bonus）。平均每轮产出 3.8 token——一次 forward 换回近 4 个 token，翻倍来自这里。
- **数数**：spec 轮占比 56%（**草稿供给率**不低——n-gram 匹配得到续写）但 182/185 轮只收 1 个 token（**草稿正确率**崩塌）：历史里 "1" 后面跟 "2"，当前 "59" 后面要的是 "60"，递增序列不自我重复，匹配到的续写几乎必错。平均 1.03 token/轮——spec 轮 forward 5 个 token 换回 1 个，持平到微亏。
- **开放**：spec 仅 1/59 轮（文本无重复，n-gram 大多提不出草稿），机制近乎不介入，x0.99 即噪声。附带口径注明：本桶 A/B 两路输出长度不等（77 vs 60 token）——开放 prompt 上浮点差被放大导致 eos 位岔开，此桶比较的是"不同长度输出的吞吐比"，量级结论不受影响。

## 3. 负载分桶方法学

三桶不是随便挑的 prompt，是按"文本是否真的自我重复"分的三类，⑨ 的逐 token 对照实验给出了判据：

| 负载类 | 定义 | 每 spec 轮平均产出 | 判定 |
|---|---|---|---|
| 真重复 | 后文逐字重现前文 | 3.8 token | 投机的甜蜜区 |
| 伪模式 | 看似有规律但序列不重复（递增/枚举） | 1.03 token | 供给率高、正确率崩，负收益区 |
| 无重复 | 开放生成 | ≈1 token | 机制近乎不介入 |

两条报告纪律由此确立：

1. **草稿供给率与草稿正确率是两个指标**，必须分开看（数数桶 56% vs 98% 退化是最尖的例子）；
2. **接受长度 α（算法侧）与加速比（系统侧）分开报**——α 决定理论上限 S=(α+1)/(1+kc)，加速比还受批 forward 成本 c 侵蚀；本仓 c 未单独测量（k+1 token 批与 1 token 批的耗时比），列后续工作。

## 4. 正确性验证

### 4.1 greedy 逐 token 等价（`compare_greedy.py`）

同一引擎实例，A 路关投机、B 路开投机，greedy 下两遍输出**逐 token 全等**：

| case | 输出长度 | spec 轮 | 停止方式 | 结果 |
|---|---|---|---|---|
| 复述型 | 70 token | 14/18（78%） | eos 同位 | PASS 全等 |
| 数数型 | 192 token | 104/185（56%） | eos 同位 | PASS 全等 |

账目验证全平：复述 12×5+1×4+5×1 = 69 恰等于 B 路产出；数数 182×1+2×2+1×5 = 191 同样平；A 路每轮恰 1 token。

**greedy 双手段互证**（M4-B 后）：`temperature=0`（分流 argmax 路径）与 τ=1e-6（温度放大路径）在双 case 上输出全等（json 比对 MATCH），且三组独立运行的 spec 统计逐字段一致——greedy 确定性可复现。

### 4.2 显存压力与抢占安全（`spec_bench.py r1`）

负载构造：8 段互异长文 ×2 = 16 条并发复述，`util=0.32`（KV 池 64 块 = 16,384 token，读实测不估算），`max_tokens=2048` + `ignore_eos`。

结果：free 块水位压至 0/64，**抢占 11 次，其中带草稿被抢 0 次**（`unmerge_spec_tokens` 回滚在工作），16 条输出全部完好（~2050 token sane）。大池对照组（无压力）preempt 0 次，真值前提成立。

如实记录：R1 的确切案发现场（merge 之后自身容量不足的 `scheduler.py:66` 分支）在 10 次观测中未出现——被抢的全部是"弹队尾"形态（本就无草稿）。该修复以三层证据定案：机制推演 + 单元测试（merge→unmerge 四字段全回滚 + 幂等）+ 绿相行为（零残留、输出 sane）。

### 4.3 stale hash 量化（`spec_bench.py hash`）

B 档（deallocate 时同步删键 + 守卫）vs A 档（依赖 `_allocate_block` 延迟清理）：

| 档位 | 满块探测 | 命中 | stale 白查 | 表残留 |
|---|---|---|---|---|
| B 档 | 1088 | 23 | **0** | 57 |
| A 档 | 943 | 9 | **0** | 61 |

结论：该负载下**两档正确性等价、白查均为 0、无可测收益差异**；B 档删键在工作（残留略少）但删掉的键无人光顾。残留主源在 **preempt / 归还路径**（块归还 free 时带登记），真修 stale 的主战场在那里（后续工作）。

## 5. 负载设计的四层系统行为

构造显存压力负载时，引擎有四层系统行为会"消化"你施加的压力，必须逐层突破（每层都在实测中撞过）：

1. **前缀缓存 1/N 效应**：N 条相同 prompt 并发，块内容同质 → 共享，显存成本 ≈ 1/N。破解：加任务编号前缀打破同质。
2. **登记时序差**：prompt 块在批后 postprocess 登记 hash（同批探测全 miss → 各自独立块），增长块即时登记（同批后续全部命中复用）——两路径行为不同。破解：靠增长块撑压力。
3. **hash 断链内容寻址**：未满块 hash=-1 不登记 → 链式前缀断裂 → 断点后的块退化为纯内容键——不同序列的对齐同文段跨序列共享。破解：各条用互异文段。
4. **spec 效率异质 → 峰值驻留 << 提交数**：各条复述难度不同 → 完成时间差 2-3 倍 → 任意时刻真驻留仅 3-5 条，早完成的块持续回血。破解：16 条 = 8 段 ×2，跨段独立使物理峰值 > 池。

（`R1_TEXTS` 八段互异文段与 `util=0.32` 即四层全破后的最终负载形态。）

## 6. 相对 #147 的修复明细

以生态内唯一先行尝试 [#147](https://github.com/GeeeekExplorer/nano-vllm/pull/147)（未合并）为参照实现，过程中发现并修复其 5 处缺陷：

| # | 缺陷 | 后果 | 修复与锚 |
|---|---|---|---|
| 1 | `propose` 缺 `max_model_len` 回退 | 全默认调用路径 TypeError | 补回退 + 回归用例 |
| 2 | 多序列比较索引错位（比较基准用 draft 侧） | 单序列无害、多序列必错 | 换 sampled 基准 + 回归用例 |
| 3 | 恰满末块条件误重置（`>0` 应为 `< block_size`） | 满块 hash 被错误清掉 | 修条件 + 回归用例 |
| 4 | 抢占（preempt）× 草稿合并（merge）无处理 | 被抢序列草稿 token 残留 | `unmerge_spec_tokens` + 单测（§4.2） |
| 5 | stale hash 删除缺同键守卫 | 同内容多块键覆盖 → KeyError | `get(h)==block_id` 守卫（#153 完整形态） |

另有结构性适配 5 条（基线漂移：本仓基线为上游 v0.2.0，#147 的 base 更旧）：移植意图、不抄行号，明细见引擎仓 git 历史。

## 7. 已知边界与后续工作

- **单轮测量**：每配置未做 3 轮取均值（工具与设计已备：k 可运行时直调 `llm.model_runner.drafter.k`，扫描模式设计完成，约 31 跑次）。
- **k=4 为默认值，未做 1-5 全扫描**：最优 k 未知，README / 简历中的 k=4 如实标注为默认配置。
- **批 forward 成本 c 未单独测量**：S=(α+1)/(1+kc) 无法做数值自检，只能做方向性对照。
- **开放生成无收益的根因**：n-gram 无模型先验，开放文本提不出草稿——这是该路线的结构性边界，非实现缺陷。
- **归还路径 stale 源**：hash 表残留主源在 preempt / 归还处（§4.3），真修列为后续工作。
- **非 eager（CUDA Graph）× 投机组合未验证**：投机批进 cudagraph 的防护已加（`run_model` 条件），但组合未跑过端到端，全项目数据均为 `enforce_eager=True` 口径。
